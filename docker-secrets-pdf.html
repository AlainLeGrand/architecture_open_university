🔐 Docker Secrets pour sécuriser les mots de passe

❌ Problème Identifié

Les mots de passe sont actuellement stockés en clair dans le fichier .env, ce qui représente un risque de sécurité majeur. Toute personne ayant accès au repository peut lire ces credentials sensibles.

✅ Solution Recommandée

Utiliser Docker Secrets pour la gestion sécurisée des mots de passe, avec encodage Base64 et ajout d'un salt pour renforcer la sécurité.

📋 Étape 1 : Créer les secrets Docker

1.1 Créer les secrets de base

Exécutez ces commandes pour chaque mot de passe :

# Secret pour le root password PostgreSQL
echo "SecureRootPassword123!" | docker secret create db_root_password -

# Secret pour le user password PostgreSQL
echo "SecureDBPassword456!" | docker secret create db_password -

# Secret pour Moodle admin
echo "MoodleAdmin789!" | docker secret create moodle_admin_password -

# Secret pour Keycloak admin
echo "KeycloakAdmin101!" | docker secret create keycloak_admin_password -

# Secret pour Nextcloud admin
echo "NextcloudAdmin202!" | docker secret create nextcloud_admin_password -

# Secret pour Grafana admin
echo "GrafanaAdmin505!" | docker secret create grafana_admin_password -

# Secret pour Drupal admin
echo "DrupalAdmin321!" | docker secret create drupal_admin_password -

# Secret pour pgAdmin
echo "change_me" | docker secret create pgadmin_password -

# Secret pour OpenAI WebUI
echo "openai-secret-key-very-long-and-secure-303" | docker secret create webui_secret_key -

# Secret pour VNC
echo "VNCSecure404!" | docker secret create vnc_password -
💡 Info : Les secrets sont stockés de manière chiffrée par Docker et montés dans les conteneurs sous /run/secrets/

🔒 Étape 4 : Encodage Base64 + Salt (Sécurité renforcée)

💡 Note : Cette étape ajoute une couche de sécurité supplémentaire en encodant les mots de passe avec un salt avant de les stocker comme secrets.

4.1 Script de création de secrets encodés

#!/bin/bash

# Fonction pour créer un secret encodé avec salt
create_secret_with_salt() {
    local SECRET_NAME=$1
    local PASSWORD=$2
    
    # Générer un salt aléatoire unique
    local SALT=$(openssl rand -base64 32)
    
    # Combiner password + salt et encoder en base64
    local ENCODED=$(echo -n "${PASSWORD}${SALT}" | base64)
    
    # Créer le secret
    echo "$ENCODED" | docker secret create "${SECRET_NAME}" -
    
    # Sauvegarder le salt dans un fichier sécurisé séparé
    echo "${SECRET_NAME}:${SALT}" >> .secrets_salts
    
    echo "✅ Secret '${SECRET_NAME}' créé avec salt"
}

# Créer tous les secrets
create_secret_with_salt "db_root_password" "SecureRootPassword123!"
create_secret_with_salt "db_password" "SecureDBPassword456!"
create_secret_with_salt "moodle_admin_password" "MoodleAdmin789!"
create_secret_with_salt "keycloak_admin_password" "KeycloakAdmin101!"
# ... autres secrets ...

# Sécuriser le fichier des salts
chmod 600 .secrets_salts
echo "✅ Fichier .secrets_salts créé et sécurisé"
echo "⚠️  IMPORTANT: Sauvegardez .secrets_salts dans un endroit sûr!"

4.2 Script de décodage dans l'entrypoint du conteneur

Pour les services qui ne supportent pas _FILE, créez un script d'entrée :

#!/bin/bash
# entrypoint.sh

# Fonction pour décoder un secret
decode_secret() {
    local SECRET_FILE=$1
    local SALT=$2
    
    if [ -f "$SECRET_FILE" ]; then
        # Lire le secret encodé
        local ENCODED=$(cat "$SECRET_FILE")
        
        # Décoder base64
        local DECODED=$(echo "$ENCODED" | base64 -d)
        
        # Retirer le salt (longueur connue: 32 caractères base64 = 44 chars)
        local PASSWORD=${DECODED:0:-44}
        
        echo "$PASSWORD"
    fi
}

# Décoder et exporter les passwords
export DB_PASSWORD=$(decode_secret "/run/secrets/db_password" "$DB_SALT")
export ADMIN_PASSWORD=$(decode_secret "/run/secrets/admin_password" "$ADMIN_SALT")

# Lancer l'application principale
exec "$@"

🔐 Bonnes pratiques de sécurité

1. Ne jamais commiter les secrets

Ajoutez à votre .gitignore :

.env
.secrets_salts
*.secret
secrets/
2. Rotation régulière des secrets 
# Supprimer l'ancien secret
docker secret rm db_password

# Créer un nouveau secret avec un nouveau mot de passe
echo "NewSecurePassword123!" | docker secret create db_password -

# Redéployer les services concernés
docker-compose up -d --force-recreate postgres moodle drupal
3. Sauvegarde sécurisée

Sauvegardez le fichier .secrets_salts dans un gestionnaire de mots de passe ou un coffre-fort sécurisé (HashiCorp Vault, AWS Secrets Manager, etc.)

⚠️ Limitations de Docker Secrets
  • Docker Secrets nécessite Docker Swarm mode (même pour un nœud unique)
  • Alternative : utiliser docker-compose secrets avec des fichiers locaux pour dev
  • Pour production : migrer vers Kubernetes Secrets ou HashiCorp Vault

🚀 Migration depuis .env vers Docker Secrets

6.1 Script de migration automatique

#!/bin/bash
# migrate_to_secrets.sh

echo "🔄 Migration des passwords du .env vers Docker Secrets"

# Lire le fichier .env
while IFS='=' read -r key value; do
    # Ignorer commentaires et lignes vides
    [[ "$key" =~ ^#.*$ ]] && continue
    [[ -z "$key" ]] && continue
    
    # Détecter les variables de type PASSWORD
    if [[ "$key" =~ .*PASSWORD.* ]] || [[ "$key" =~ .*SECRET.* ]]; then
        # Convertir en nom de secret (minuscules, underscores)
        secret_name=$(echo "$key" | tr '[:upper:]' '[:lower:]')
        
        # Créer le secret si pas déjà existant
        if ! docker secret inspect "$secret_name" &>/dev/null; then
            echo "$value" | docker secret create "$secret_name" -
            echo "✅ Secret créé: $secret_name"
        else
            echo "⚠️  Secret existe déjà: $secret_name"
        fi
    fi
done < .env

echo "✅ Migration terminée!"
echo "⚠️  N'oubliez pas de mettre à jour docker-compose.yml"
